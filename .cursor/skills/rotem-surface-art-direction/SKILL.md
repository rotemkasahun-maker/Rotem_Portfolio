# ROTEM Surface Art Direction

## Purpose
Use when the page feels too flat, too white, too segmented, too card-like, or when color/surface treatment needs art direction.

## Core principle
Surface is a compositional material, not a section-labeling system.

Do not solve visual rhythm by assigning a different background color to every section.
Do not treat muted colors as automatically subtle.
Do not use whole-width colored wrappers unless the existing design explicitly calls for them.

## ROTEM visual bias
Prefer:
- warm neutral paper families
- tonal depth before hue contrast
- partial surfaces instead of full-section fills
- broad but quiet editorial planes
- edge-entering fields, cropped planes, evidence backplates, or localized tonal shifts
- one accent family with discipline rather than many semantic colors
- asymmetry, negative space, and material/paper logic

Avoid:
- alternating section stripes
- rainbow segmentation
- card stacks
- dashboard color coding
- SaaS landing-page gradients
- decorative blobs
- excessive rounded containers
- shadows used to manufacture hierarchy
- "one color per chapter" logic

## Workflow
1. Inspect the rendered page or screenshot before proposing changes.
2. Identify whether the real problem is hue, value, temperature, scale, geometry, or repetition.
3. Describe the current failure in visual terms before editing.
4. Preserve layout, copy, typography, motion, and evidence unless the task explicitly includes them.
5. Propose at most 2-3 surface strategies.
6. Prefer the smallest strategy that changes page rhythm.
7. Implement with isolated variables/selectors so rollback is easy.
8. Render and compare against the baseline.

## Surface strategy library
Use selectively, never all at once:
- paper-tone shift behind a key statement only
- wide plane beginning or ending off-grid
- evidence-only surface field
- shallow tonal band that does not map 1:1 to a section
- inset or offset neutral field with no card border
- one restrained accent used as a line, metadata cue, or small plane
- change in warm/cool neutral temperature rather than obvious hue

## Palette discipline
- Start from the approved project palette.
- Build a neutral family by changing lightness/temperature subtly.
- Test colors in context, not as swatches only.
- If the eye reads "green section / yellow section / pink section," the treatment is too semantic or too strong.
- If the background becomes more noticeable than the evidence or key statement, reduce it.
- Do not change text colors unless contrast requires it.

## Failure test
FAIL the treatment if any of these are true:
- the page starts to resemble slides
- sections become visually boxed
- color announces structure more loudly than typography/layout
- multiple hues compete for attention
- the treatment feels like generic AI-generated UI
- the original ROTEM editorial DNA becomes weaker
