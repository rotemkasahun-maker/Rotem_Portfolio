# ROTKA Approved Pattern Library — Depth Patterns v1

Status: Candidate library. Promote only after visual QA and explicit approval.

## Pattern A — Supported Artifact
Real media foreground + subtle paper-alt support surface + 8–28px offset + soft ambient shadow. Avoid centered backing cards, heavy shadows, and fake device frames.

## Pattern B — Featured Artifact
One real artifact gets stronger narrative presence through larger scale, more negative space, asymmetric placement, and optional restrained reveal.

## Pattern C — Evidence Pair
Two related artifacts with unequal hierarchy. Primary larger, secondary smaller/offset. Avoid generic 50/50 galleries.

## Pattern D — Statement Pause
Large, high-contrast statement with strong negative space and minimal surrounding noise.

## Pattern E — Opening Background Shift
Distinct opening surface/background treatment that later transitions to the normal portfolio canvas. No arbitrary gradients or unrelated brand colors.

## Pattern F — Scan Emphasis
Emphasize selected words/clauses with weight, contrast, scale, line break, or isolation. Do not gray out entire paragraphs.

## Pattern G — Subtle Scroll Growth
Media progresses from about 0.985–0.995 to 1, max around 1.01–1.03. Felt more than noticed.

## Pattern H — Tactile Hover
Tilt max 1–2deg, translate max 4px, subtle shadow response, optional contextual cursor label.

## Pattern I — Contextual Cursor Label
Small action-oriented hover labels such as “Say hi”, “Open”, or “View project”. Use only real action meaning; do not invent cute filler copy.

## Pattern J — Living Media Loop
Short silent loop of real UI/state changes. Best for Family Finance and real product flows. Never fake product demos.

## Pattern K — TL;DR / Detailed Mode
Candidate for long case studies. Strong fit for Family Finance; not default for short 106.

## Pattern L — Rounded Media Surface
Restrained radius on raw screenshots where appropriate. Rounded is allowed; rounded-everything is not.

## Promotion Rule
A candidate becomes APPROVED only after:
- implementation in a real page
- visual QA
- explicit user approval
- no invented content
- responsive correctness
- reduced-motion correctness

Record when promoted:
- page where approved
- screenshot/reference
- exact implementation mechanism
- reusable constraints
- mobile behavior
- motion behavior
