# DESIGN_RULES.md

## Portfolio visual direction

The portfolio must feel like a high-end editorial catalogue of ideas, objects and product decisions.

Primary characteristics:
- object-led, not UI-card-led
- strong controlled asymmetry
- intentional large crops
- lots of negative space
- editorial rhythm
- real objects / evidence over decoration
- authored composition, not generic template composition
- refined, restrained typography
- product UI appears as polished evidence inside the portfolio, not as the visual language of the whole site

## Visual references / translation principles

Use the logic of:
- oversized object scale and crop
- editorial spreads with one dominant object and quiet supporting text
- catalogue / specimen / numbered archive layouts
- object fields
- taxonomy and table-of-contents logic
- varied section silhouettes
- controlled accumulation of evidence

Do not literally imitate proprietary designs. Translate their composition logic only.

## Never use as default portfolio language

- SaaS dashboard aesthetic
- generic UX portfolio cards
- stacked project cards
- startup gradients
- generic pastel card systems
- doodles
- handwritten arrows
- sticky notes
- tape
- scrapbook styling
- random decorative shapes
- red squiggles / annotation paths
- random rotations
- generic AI-generated minimal portfolio styling
- research-board aesthetic

## Typography

Direction:
- editorial sans
- smaller / lighter / tighter than generic landing-page typography
- strong hierarchy without oversized startup-style hero copy
- display type only when composition genuinely calls for it
- restrained small labels

## Color

Portfolio shell:
- clean ivory / off-white
- charcoal
- warm-grey rules / borders
- avoid muddy beige

Product UI:
- may be slightly creamier / softer than the portfolio shell

## Homepage

Current implementation is NOT visually approved.

Homepage should be:
- object-led
- asymmetrical
- visually authored
- one dominant physical object where appropriate
- copy secondary to composition
- no generic UX-project metadata as decoration
- no default card layout

Do not automatically switch between fridge and lettuce concepts. The concept must be explicitly selected before implementation.

## Work index

Use catalogue / archive logic.
Prefer:
- numbering
- taxonomy
- specimen / index feeling
- asymmetric editorial structure

Avoid project cards.

## Family Finance

Portfolio case study must read as an editorial product story.

Product visuals must read as mobile app evidence, not desktop dashboard.

Approved story structure:
1. Opening / collecting / overload
2. Everything in one place
3. Automation / boring parts
4. Ask only when needed
5. Item-level understanding
6. Insights
7. Motivation / Madrid
8. Current state
9. Ending / poke around

Sections 1–2 structure is preserved and must not be reopened without explicit instruction.

## Hard workflow visual rule

Before finishing any visual task, ask:

“Could this screen belong to any random AI-generated minimal UX portfolio?”

If yes:
FAIL. Revise.

## Scope rule

Never redesign unrelated sections.
Never change approved assets without instruction.
Never invent copy.
Use TODO when copy is not approved.
